# 调度算法评价标准 (bench)

用真实跑分的事件流做 **attempt 级回放**,把"调度策略"从"模型能力"中隔离出来量化评估。
任何调度相关改动(`runner.ts` 的选题/预算/重试/hint/熔断逻辑)合并前必须跑这套 bench。

## 指标定义

| 指标 | 定义 | 方向 |
|---|---|---|
| **M1 总点数** | 回放终局总得分 | 越高越好(主指标) |
| **M2 得分提前度** | `Σ pts_i×(T−t_i) / (名目总分×T)`,同样的分拿得越早越高 | 越高越好 |
| **M3 空转率** | 零分 attempt 消耗的 worker 分钟 / 总 worker 分钟 | 越低越好 |
| **M4 最长真空** | 相邻得分事件的最大间隔(含收尾段),分钟 | 越低越好 |
| **M5 提示效率** | 兑换提示后最终得分的题数 / 兑换提示总题数(离线统计) | 越高越好 |
| **M6 覆盖率** | 至少拿到一次 attempt 的题目数 | 不许下降(防饥饿) |
| **M7 解出题数** | 终局 solved 数 | 越高越好 |

## 合并门禁(改动是否可接受)

1. **M1 不回退**(同数据集对比 baseline)。
2. **M3 或 M2 至少一项改善 ≥3%**,且不牺牲 M1。
3. **M6 不下降**(不允许为了省预算饿死题目)。
4. 参数变化需通过敏感性扫描(在 ±50% 参数范围内指标单调可解释,无悬崖)。

## 使用方法

```bash
# 1. 从赛事平台导出的事件流 CSV 提取数据集
python3 bench/extract_dataset.py <events.csv> bench/dataset-<run>.json

# 2. 回放对比 baseline(现行策略) vs optimized(优化策略) + 敏感性扫描
python3 bench/simulate.py bench/dataset-<run>.json
```

新增策略:改 `bench/simulate.py` 里的 `Policy`/`OPTIMIZED`,或在 `main()` 加扫描行。

## 诚实边界(读数前必读)

- 经验数据里从未解出的题,在任何调度策略下都不得分(**保守下界**)——
  因此 M1 的差异只反映:卡死恢复提前(熔断重启)、末段提示转化(what-if)、重试时机变化。
  调度对 M1 的真实贡献被低估,对 M2/M3/M4 的贡献是准的。
- `p_convert>0` 的行是**能力 what-if**(假设更强模型/更有效提示能转化未解题),
  用来给"要不要升级模型"定决策阈值,不算调度的直接功劳。
- 未解题的名目分值在事件流中不可见,数据集中标注 `score_estimated: true`,
  仅用于 what-if,不影响 baseline 复现校验。

## 当前基线 (run-9874, 2026-08-16 正赛第一轮)

baseline 回放复现校验: **12860 点 / 26 题 / 覆盖 40** —— 与实际战绩完全一致, harness 可信。

| 策略 | M1 | M2 | M3 空转 | M4 真空 |
|---|---|---|---|---|
| baseline(现行) | 12860 | 0.397 | 743 min (73%) | 85 min |
| optimized(cap=60, att=3) | 12860 | 0.412 | 722 min (71%) | 90 min |
| optimized(cap=40, att=3) | 12860 | 0.412 | 554 min (65%) | 90 min |
| **final: cap=60, att=2(已落地默认)** | 12860 | 0.412 | **677 min (70%)** | 90 min |
| 激进: cap=40, att=2 | 12860 | 0.412 | **528 min (63%)** | 90 min |
| optimized + 末段转化 p=0.2 (what-if) | ~13900 | 0.416 | 700 min | 74 min |

三方案深度对比(含压力情景, 见 `bench/compare3.py` + 报告):
- cap 的真正作用不是省空转(后期 pass 会把省下的预算再烧进额外重试),而是**是否切断
  "忙时 35~60min 但重试本可解出"的题的上行保险**: cap=40 在"中占用组"情景下丢 +1080 分, cap=60 全保留。
- max_attempts 才是空转主杠杆(实测无题靠第 3 次尝试得分): att=2 比 att=3 省 45min 且情景上行零损失。
- 最终默认 `RETRY_BUSY_CAP_MIN=60 / MAX_ATTEMPTS=2`: 上行保险全保留 + 空转 -9%。
  若下一场确认难度仍极高或 token 配额吃紧, 改 `RETRY_BUSY_CAP_MIN=40`(空转再降 22%, 约省 1 亿+ tokens)。

结论:调度优化在同分(M1 受经验数据封顶)下把得分提前 3.6%、空转降 9%(激进 cap=40 可降 27%);
M1 的进一步提升依赖能力杠杆(更强模型/提示转化),p=0.2 时 +1000 分量级。
